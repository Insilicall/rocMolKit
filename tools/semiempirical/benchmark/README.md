# PM6_D GPU batch-SCF throughput benchmark (secondary / perf-only)

This is a **performance** benchmark for the batched on-device PM6_D SCF
(`scfBatchDGpu`) on an AMD **gfx1200** (RDNA4) via the rocmolkit devel
container. It is *not* a correctness test — correctness (GPU == CPU, bit-exact
to MOPAC) lives in `tools/semiempirical/validate_*` (see
`validate_gpu_cpu.py`). Treat the numbers here as a performance characterization
of the *throughput* path, not part of the core engine contract.

## What it measures

For a batch of real, ETKDG-embedded drug-like molecules it times:

* the **GPU batch** path `scfBatchDGpu` — one molecule per GPU thread, the whole
  H_core → Fock → diagonalize → density → mixing loop to self-consistency on the
  device — reported as a *cold* (first call, includes one-time HIP init/JIT/H2D)
  and a *steady-state* (best of N repeats) throughput, and
* the **CPU baseline** `pm6dCharges` looped over the same set,

emitting molecules/sec, atoms/sec, the GPU/CPU speedup, convergence rate, and a
charge-conservation sanity check (`sum(q) == net charge`).

## Files

| file | role |
|------|------|
| `bench_pm6d_gpu.py`     | builds the molecule batch (RDKit/ETKDG), serializes it, drives the hipcc build + run, writes `results.json` |
| `bench_pm6d_driver.cpp` | hipcc driver: loads the binary batch, times `scfBatchDGpu` + the CPU loop, prints `RESULT_JSON:` |
| `results.json`          | last recorded run (regenerated by the script) |

## Reproduce

From the repo root, on a host with an AMD GPU and the `rocmolkit:devel-local`
image:

```sh
docker run --rm --device /dev/kfd --device /dev/dri -e HIP_VISIBLE_DEVICES=0 \
  -v "$PWD":/work -w /work rocmolkit:devel-local \
  python3 tools/semiempirical/benchmark/bench_pm6d_gpu.py --target 300 --max-atoms 25
```

(The script also invokes docker itself if run on the host outside the
container; set `DOCKER_IMAGE` or `--image` to override.)

Useful flags:

* `--target N`      batch size (molecules; replicated with tiny coordinate jitter).
* `--max-atoms K`   drop base molecules larger than K atoms (**important** — see below).
* `--gpu-repeats`, `--cpu-repeats`  timing repeats (best-of).
* `--no-cpu`        skip the (slower-to-loop) CPU baseline.

## Important: the one-thread-per-molecule model

`scfBatchDGpu` runs **one full SCF per GPU thread**. There is *no* intra-molecule
parallelism: a single RDNA4 lane does the entire dense diagonalization every SCF
iteration. Consequences:

* **Wall time is dominated by the single largest molecule** in the batch. One
  ~70–80-atom molecule (e.g. atorvastatin) at the 800-iteration cap can stall a
  whole batch for minutes. Use `--max-atoms` to bound this — the benchmark caps
  at 25 atoms by default in the docs run.
* At drug-molecule sizes the per-lane serial diagonalizer does **not** beat a
  cache-friendly CPU SCF loop; the measured speedup is **< 1x** (see
  `docs/SEMIEMPIRICAL_DESIGN.md` → *Benchmarks*). The batch path's value is
  *correctness* (bit-exact, fully on-device, no host round-trips per molecule),
  not raw throughput at these sizes. It is best suited to **large batches of
  small molecules** (its original "one d-atom + hydrogens" scope).

These are honest, measured characteristics on gfx1200 — not estimates.
